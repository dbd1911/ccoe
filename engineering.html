Mandatory Technical Standards

Non-Negotiables in Every Design

Identity & Access Management

  • MFA: phishing-resistant (CAC/PKI or FIDO2) for all users; mandatory for privileged access — no exceptions, no OTP fallback for admins
  • RBAC: role definitions documented in the SSP; access recertification every 90 days for privileged, 180 for standard
  • Privileged sessions via jump host / PAW only; no direct admin from user workstations
  • Service accounts inventoried, non-interactive, credential rotation ≤ 90 days

Logging & Auditing

  • All systems forward to the enterprise SIEM — local-only logging fails assessment
  • Minimum events: authentication, privilege use, configuration change, data export
  • Retention: 1 year online, 5 years archived; clock sync to authoritative NTP
  • Log integrity protected (append-only or hash-chained store)

Cryptographic Standards

  • FIPS 140-validated modules only; TLS 1.2 minimum, 1.3 preferred
  • CUI at rest: AES-256 full-disk or database-level encryption
  • Key management documented in the SSP; no hardcoded keys — pipeline secret scanning enforced
  • Begin CNSA 2.0 / post-quantum transition planning for systems with >5-year horizons

STIG Execution Handbook

  • Apply current-quarter STIG/SRG baselines from the tracked version list
  • Baseline system images maintained per OS family — start hardened, don't harden later
  • Every open finding carries a justification or a POA&M; "will fix later" is not a justification
  • SCAP-scan where possible; manual .ckl with evidence where not
Pipeline Controls & ARB Intake

From Commit to Authorized

DevSecOps Pipeline Controls

Required gates for any pipeline feeding an authorized boundary (and the precondition for the Agile ATO pathway):

  • Signed commits + protected main branch with mandatory review
  • SAST and dependency (SCA) scanning — build fails on unmitigated critical/high
  • Container/image scanning against hardened base images
  • SBOM generated per release artifact, archived with the build
  • DAST in staging before any production promotion
  • Deployment audit trail retained in the SIEM

Architecture Review Board (ARB)

The ARB reviews new system designs and significant architecture changes before resources are committed.

  • Cadence: first and third Wednesday monthly
  • Submit: intake package 10 business days prior — concept, boundary sketch, data types, blueprint deviation list
  • Outcome: approved / approved-with-conditions / rework, recorded in the decision archive
  • Blueprint-conformant designs qualify for expedited review (single session)
